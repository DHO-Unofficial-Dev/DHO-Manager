구성요소 API

하나의 팩은 필요한 구성요소만 선언할 수 있습니다. 사용자는 설치할 때 구성요소를 선택하며 활성 팩 스택에서 우선순위가 높은 동일 구성요소가 최종값이 됩니다.

실행 가능한 참조

완성 예제에서 최소 거점 팩과 모든 화면·마커 토큰을 담은 테마 팩을 소스와 설치 파일로 함께 확인할 수 있습니다.

공통 선언

components 아래의 각 항목에는 안정 ID와 표시 이름이 필요합니다. 외부 JSON을 읽는 데이터 구성요소는 파일 경로를 추가로 선언합니다.

키데이터 파일합성 방식
mapDatacoastline, seaRegions가장 높은 활성 팩 하나
poiDatasource가장 높은 활성 팩 하나
markerSet선택 이미지 자산가장 높은 활성 팩과 안전 폴백
infoPanelSkin없음가장 높은 활성 팩 하나
steeringHudSkin없음가장 높은 활성 팩 하나
mapHudSkin없음가장 높은 활성 팩 하나

mapData

게임 세계 좌표 16384×8192의 해안선과 해역 면을 제공합니다. 각 JSON은 별도 스키마 검증과 좌표 범위 검사를 통과해야 합니다.

"mapData": {
  "id": "community.example.world-map",
  "name": "예시 세계 지도",
  "dataVersion": "2026-08-06",
  "coordinateSpace": "game 16384x8192",
  "coastline": "components/map-data/coastline.json",
  "seaRegions": "components/map-data/sea-regions.json"
}

해역은 대표점이 아니라 폴리곤 배열입니다. 표시 면이 없는 구획용 해역의 빈 polygons도 유효합니다. 세계 X축은 순환하므로 경계 0/16384를 지나는 도형은 규격에 맞게 분할해야 합니다.

poiData

추가 거점, 내장 거점 좌표 대체 또는 내장 거점 숨김을 원자적으로 제공합니다.

{
  "pois": [
    {
      "id": "community.example.my-port",
      "name": "예시 항구",
      "type": "port",
      "x": 15784,
      "y": 3205
    },
    {
      "id": "community.example.my-inland-city",
      "name": "예시 내륙도시",
      "aliases": ["예시 내륙"],
      "type": "inland_city",
      "x": 15748,
      "y": 3180,
      "coordinateRole": "display",
      "entrancePoiIds": ["community.example.my-port"]
    }
  ],
  "coordinateOverrides": [],
  "hiddenPoiIds": []
}
필드제한설명
pois최대 10,000내장 ID와 충돌하지 않는 새 거점
type열거형port, guild_city, landing, outskirts, inland, inland_city, private_farm, sea
coordinateRolesailing/display표시 전용 좌표는 목적지·도착 판정에 직접 사용하지 않음
entrancePoiIds1~16표시 전용 거점으로 들어가는 실제 항구·상륙지 또는 연결 거점
coordinateOverrides내장 poiId내장 이름과 관계를 유지하고 좌표만 변경
hiddenPoiIds내장 poiId다른 거점의 입구 관계를 끊지 않는 범위에서 숨김

markerSet

선박, 경로점, 목적지, 거점과 개인 표식의 벡터 토큰 또는 이미지 슬롯을 정의합니다. 이미지가 없는 슬롯은 같은 팩의 벡터 선언으로, 유효하지 않은 선택은 내장 기본값으로 복구됩니다. 아래 코드는 필수 벡터 토큰을 생략하고 이미지·추가 표식 부분만 보인 발췌입니다.

"markerSet": {
  "id": "community.example.markers",
  "name": "예시 마커",
  "assets": {
    "supply": {
      "path": "components/markers/supply.png",
      "displayWidth": 24,
      "displayHeight": 24,
      "anchorX": 0.5,
      "anchorY": 0.5,
      "rotateWithHeading": false
    }
  },
  "slots": {
    "ship": "ship",
    "automaticWaypoint": "auto-waypoint"
  },
  "personal": {
    "customTypes": {
      "community.example.supply": {
        "name": "보급지",
        "fallbackIcon": "port",
        "asset": "supply"
      }
    }
  }
}

추가 개인 표식 유형은 팩당 최대 32개입니다. ID에는 제작자 네임스페이스를 포함하고 name은 1~40자, fallbackIcon은 star, port, trade, danger, discovery, memo 중 하나를 사용합니다.

2.1.x 호환

automaticWaypoint, route.automatic, personal.customTypes는 선택 필드입니다. 필드가 없는 1.1.x 팩도 계속 동작하고 새 앱이 내장 기본값을 보충합니다.

infoPanelSkin

항해 정보 패널의 색과 프레임을 정의합니다. 선택적 navigator 객체는 Manager 본체가 아니라 네비게이터 메뉴·표면에만 적용됩니다.

그룹주요 필드소유 범위
colorspanelBackground, primaryText, accent, status, arrival*정보 패널
frameborderWidth, cornerRadius, backdropBlur, shadow정보 패널
navigator.colorsbackground, surface, text, line, accent, danger, focus네비게이터 GUI
navigator.cornerRadius0~허용 범위네비게이터 GUI

steeringHudSkin

조향 HUD의 중립색·표면, 눈금 투명도와 중앙 표식 치수를 정의합니다. guidanceColors를 생략하면 기존 colors.neutral에서 파생합니다.

"guidanceColors": {
  "direction": "#E8873A",
  "target": "#4FD8E0",
  "aligned": "#6FA34B",
  "centerMarker": "#E7C64B"
}

mapHudSkin

지도 HUD 상태창의 색·프레임과 지도 시각 언어를 정의합니다. mapTheme은 바다·육지·해안선·해역 색을, navigationTheme은 실제 이동·나침반·마우스·항적·목적지 경로선의 색과 패턴을 제공합니다.

팩과 사용자 설정의 분리

팩은 색상과 solid·dashed·dotted 패턴을 소유합니다. 사용자의 표시 여부, 위치, 크기, 투명도와 선 굵기는 팩을 바꿔도 유지됩니다.

appIcon

열려 있는 네비게이터 창 아이콘을 교체합니다. 매니저와 네비게이터가 공유하는 트레이 아이콘은 리소스팩의 영향을 받지 않습니다.

"appIcon": {
  "window": "components/app-icon/window.png"
}

파일은 512KB 이하, 한 변 16~512px의 정사각 PNG여야 합니다. 활성 팩이 여럿이면 설치 스택 우선순위가 가장 높은 팩의 appIcon을 적용하며, 팩 비활성화·삭제 시 내장 아이콘으로 복귀합니다.

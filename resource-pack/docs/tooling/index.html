제작 도구

Node.js 20 이상에서 같은 명령으로 Windows, macOS와 Linux용 팩을 검증하고 패키징할 수 있습니다. 도구 묶음은 공개 페이지에서 받을 수 있습니다.

권장 작업 흐름

1. 폴더 검사

node tools/validate-pack.mjs ./my-pack

색상 형식, 필수 필드, 범위 초과, 존재하지 않는 자산 참조와 지원하지 않는 파일을 패키징 전에 확인합니다.

2. 팩 생성

node tools/build-dho-pack.mjs \
  ./my-pack \
  ./dist/community.example.navigation-0.1.0.dho-pack

도구는 원본을 직접 수정하지 않고 임시 복사본에서 files SHA-256을 채운 뒤 압축합니다. 기존 출력 파일을 조용히 덮어쓰지 않습니다.

3. 최종 아카이브 검사

node tools/verify-archive.mjs \
  ./dist/community.example.navigation-0.1.0.dho-pack

배포·업로드 전에 반드시 최종 파일을 검사합니다. 폴더 검증 성공은 패키징 결과의 무결성을 보장하지 않습니다.

PowerShell 도구

Windows 저장소 작업 환경에서는 기존 PowerShell 스크립트도 사용할 수 있습니다.

.\scripts\build-dho-pack.ps1 `
  -SourceDirectory .\my-pack `
  -OutputPath .\dist\my-pack.dho-pack

같은 출력 파일을 의도적으로 교체할 때만 -Force를 추가합니다. 커뮤니티 제작자가 운영체제에 관계없이 공유하기에는 Node 도구를 권장합니다.

메시지 유형주요 원인해결

구성요소 의존성없는 구성요소, 자기 참조, 순환같은 팩 내부의 단방향 의존성만 선언

배포 전 점검표

  1. packId와 publisher.id가 제작자 네임스페이스를 사용합니다.
  2. 같은 팩의 업데이트는 ID를 유지하고 SemVer만 올렸습니다.
  3. 모든 데이터·이미지의 라이선스와 출처를 적었습니다.
  4. validate-pack, build-dho-pack, verify-archive가 순서대로 통과합니다.
  5. DHO Navigator 설치 대화상자에서 구성요소, 추가 표식과 교체 대상을 확인했습니다.
  6. 팩 비활성화·삭제 시 내장 기본값으로 안전하게 돌아옵니다.

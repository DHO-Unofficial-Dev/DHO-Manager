사람이 이해하고, AI도 실행하는 제작 흐름

이 문서의 기준은 사람에게 읽히는 API 문서입니다. 같은 규격을 JSON Schema와 llms.txt로도 제공하여 IDE나 AI 에이전트가 추측 없이 작업하도록 돕습니다.

AI에게 건넬 주소

https://manager.dhoport.app/llms.txt 하나를 먼저 읽히세요. 세부 규격, 스키마, 예제와 검증 도구의 정식 주소가 모두 연결되어 있습니다.

어떤 방법을 쓸까

방법적합한 작업결과
브라우저 생성기추가 거점, 기본 화면 색상과 항해선 테마즉시 내려받는 .dho-pack
Node 제작 도구전체 테마, 이미지 마커, 여러 파일, 반복 배포검증·해시·압축을 재현 가능한 명령으로 처리
AI + Node 도구스키마를 따라 초안을 만들고 오류를 반복 수정사람이 검토할 소스 폴더와 검증된 아카이브

공통 작업 순서

  1. 구성요소 목록에서 바꿀 범위를 고릅니다.
  2. 가장 가까운 완성 예제를 복사하고 고유한 packId, 제작자, 버전을 지정합니다.
  3. 색상·마커·거점 파일을 편집합니다. JSON 편집기는 JSON Schema를 연결할 수 있습니다.
  4. 아래 세 명령을 순서대로 실행합니다.
  5. Manager에서 설치 미리보기와 실제 HUD·네비게이터 화면을 확인합니다.
node tools/validate-pack.mjs ./my-pack
node tools/build-dho-pack.mjs ./my-pack ./dist/my-pack.dho-pack
node tools/verify-archive.mjs ./dist/my-pack.dho-pack

AI에 요청하는 예시

https://manager.dhoport.app/llms.txt 를 먼저 읽어라.
DHO Manager 2.1.x용 formatVersion 1 리소스팩을 만들어라.
목표: 짙은 바다색 GUI, 청록색 항적, 작은 자동 보조점.
visual-theme 완성 예제를 기반으로 하고 원본 폴더도 보존하라.
validate → build → verify를 모두 통과시킨 뒤
변경한 토큰과 최종 .dho-pack 경로를 보고하라.

AI가 ZIP을 손으로 만들거나 검증기를 생략하게 두지 마세요. 색상과 모양은 팩의 영역이고 HUD 위치·크기·투명도 같은 개인 배치는 사용자 설정의 영역입니다.

완료 기준

  • UTF-8 manifest.json과 필요한 정적 파일이 원본 폴더에 남아 있습니다.
  • files SHA-256은 빌드 도구가 생성하며 수동으로 꾸미지 않습니다.
  • 세 검증 명령이 모두 성공합니다.
  • 기존 2.1.x 팩에서 알 수 없는 새 필드는 무시할 수 있도록 선택 필드로만 확장합니다.
  • Manager 설치 화면에서 썸네일, 구성요소, 추가 표식 수를 사람이 확인합니다.
